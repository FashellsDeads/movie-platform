## Зачем

Три домашних задания курса React, которые сдаются преподавателю и защищаются устно:

## ДЗ №12 — Advanced Components Patterns

### Что меняется в существующих компонентах

Задание описывает API Button, Card и Modal. В CineVibe компоненты с такими именами уже есть, но с другим API. Их приводим к заданию, потому что в №14 они станут общими компонентами `common/`.

- **Button:** надпись передаётся через `children` вместо `text`, `disabled` вместо `isDisabled`. Варианты: `primary`, `secondary`, `danger`, плюс существующий `outline`, который используется на сайте. Остальные props (`type`, `onClick`, `aria-*` через rest) пробрасываются в `<button>`. Все места вызова на сайте переводятся на новый API.
- **Card:** становится универсальной: `children`, необязательные `title` и `size` (`small`/`medium`/`large`), остальные props пробрасываются в корневой элемент. Про фильмы Card ничего не знает. Нынешняя карточка фильма переименовывается в **MovieCard** (в №14 она станет `product/ProductCard`) и внутри строится на Card.
- **Modal:** `title` становится необязательным. Без него содержимое полностью задаётся через `children`, как в примере задания. Закрытие по Escape и по клику на фон остаётся.

### Новые компоненты

Все новые компоненты лежат в `src/components/<Name>/` по текущей структуре проекта.

- **Layout:** props `header`, `sidebar`, `children`, `footer`. Слоты без значения не рендерятся. Это чистая композиция, без логики.
- **Tabs:** Compound Component `Tabs`, `Tabs.List`, `Tabs.Tab`, `Tabs.Panel`. Выбранная вкладка хранится в `Tabs`, части получают её через Context.
  - Вкладка и панель связываются по порядку, как в примере задания: n-й `Tab` открывает n-ю `Panel`. Индексы раздаются без ручного `index`.
  - Доступность: `role="tablist"`/`tab`/`tabpanel`, `aria-selected`, `aria-controls`.
- **Toggle:** `Toggle`, `Toggle.Button`, `Toggle.Content`. Состояние открыт/закрыт хранится в Context. У `Toggle.Button` текст по умолчанию «Показать»/«Скрыть», его можно заменить через children.
- **Accordion (дополнительное задание):** `Accordion`, `Accordion.Item`, `Accordion.Title`, `Accordion.Content`. Prop `multiple`: без него открыт только один элемент, с ним несколько. Связь частей через Context, `Accordion.Item` даёт свой Context с id элемента.
- **DataLoader (render props):** `<DataLoader loadData={fn}>{(data, loading, error) => …}</DataLoader>`. Сам вызывает `loadData` в эффекте, хранит data/loading/error и игнорирует ответ после размонтирования. Как показывать данные, решает внешний компонент.
- **withLoading (HOC):** `withLoading(Component)` возвращает компонент с prop `isLoading`. Пока `isLoading` истинно, показывает «Loading...». Иначе рендерит исходный компонент со всеми остальными props без изменений. Задаётся `displayName` (`withLoading(UserList)`), чтобы компонент был понятен в DevTools.

### Страница `/patterns` (PatternsPage)

Ссылка на неё стоит в подвале, раздел «Для разработчиков», а не в главном меню. Страница построена на `Layout`: в header заголовок, в sidebar оглавление со ссылками-якорями на секции, в footer подпись. Каждая секция показывает один паттерн на данных кинотеатра:

- **Card:** две-три карточки с разным содержимым и разными `size`.
- **Button:** все варианты плюс `disabled`.
- **Modal:** «Удалить билет из корзины?» с кнопками «Отмена» и «Удалить» (`danger`).
- **Tabs:** «Описание / Сеансы / Отзывы» для одного фильма.
- **Toggle:** «Подробнее о зале».
- **Accordion:** FAQ кинотеатра (возврат билетов, парковка, дети) с переключателем режима «один / несколько».
- **DataLoader:** загрузка списка фильмов через существующий `cinemaApi` с задержкой, поэтому видно и loading, и ошибку (оффлайн), и данные. Плюс кнопка «Перезагрузить».
- **withLoading:** `MovieListWithLoading = withLoading(MovieList)`, кнопка «Загрузить заново» включает `isLoading` на секунду. Видно, что исходный компонент продолжает получать свои props (например, заголовок списка).

### Тесты №12 (в существующем стиле, рядом с компонентами)

- **Tabs:** клик по вкладке показывает её панель и скрывает остальные.
- **Toggle:** контент появляется и исчезает.
- **Accordion:** в обычном режиме открывается только один элемент, в режиме `multiple` несколько.
- **DataLoader:** loading → данные, loading → ошибка (через отложенный промис).
- **withLoading:** показывает «Loading...», затем исходный компонент с переданными props.
- **Card/Button/Modal:** рендерят children. Modal закрывается по Escape. Button `disabled` не вызывает `onClick`.

## ДЗ №13 — Advanced Components Patterns II

### Компоненты ввода

- **Input:** один компонент для обоих режимов.
  - Если передан `value`, это controlled: значение задаёт родитель, а `onChange` получает строку, как в задании (`onChange={setName}`).
  - Иначе это uncontrolled: `defaultValue`, значение живёт в DOM.
  - Есть label, error и проброс остальных props. `ref` пробрасывается на `<input>`, в React 19 как обычный prop.
- **SearchInput:** использует `forwardRef`, задание требует именно его. Ref указывает на настоящий DOM-элемент `<input type="search">`.
- **CustomInput:** через `useImperativeHandle` отдаёт родителю `focus()`, `clear()`, `getValue()`. Сам DOM-элемент наружу не выходит.

### Form Builder

**FormProvider** держит состояние через `useReducer(reducer, initialState)`.
- Состояние: `{ fields, values, errors }`.
- Actions: `ADD_FIELD`, `REMOVE_FIELD`, `UPDATE_FIELD`, `UPDATE_VALUE`, `RESET_FORM`, `SET_ERRORS`. Все изменения идут только через `dispatch`.
- Через Context отдаются: значения, ошибки, `updateValue`, `addField`, `removeField`, `updateField`, `resetForm`, `validate`.

**State Reducer Pattern.** `<FormProvider reducer={customReducer}>`, где `customReducer(state, action, defaultReducer)`. Внешний reducer может переопределить одно действие и для остальных вызвать стандартный. Стандартный reducer экспортируется, чтобы родитель мог на него опереться.

**Undo/Redo (дополнительное задание).** История `{ past, present, future }` и actions `UNDO`, `REDO`.
- В историю попадают только изменения структуры формы: `ADD_FIELD`, `REMOVE_FIELD`, `UPDATE_FIELD`. Ввод значений в Preview в историю не попадает, иначе Undo откатывал бы по одной букве.
- `RESET_FORM` очищает историю.

**Компоненты формы** получают состояние из Context, без длинной цепочки props.
- **FormBuilder:** список полей и кнопка «Добавить поле».
- **FieldEditor:** название, тип (`text`/`email`/`number`/`select`), «обязательное», удаление. Для `select` ещё список вариантов.
- **DynamicField:** по описанию поля сам выбирает, какой input отрисовать. В №14 добавятся типы `checkbox`, `radio`, `password`.
- **FormPreview:** форма глазами конечного пользователя, валидация и кнопка «Submit». После отправки на странице показывается объект значений (JSON).
- Рядом в режиме Edit живьём показывается текущая структура формы (JSON полей).
- Режимы **Edit / Preview** переключаются кнопками.

**Валидация:**
- обязательное поле не может быть пустым;
- email должен быть в правильном формате;
- number должен быть числом.

Функции валидации переиспользуют `utils/validation.js`, где это возможно.

### Страница `/form-builder`

Ссылка стоит в подвале, раздел «Для разработчиков», рядом с `/patterns`. Тематика — «Анкета зрителя для закрытого показа». Стартовые поля: Имя, Email, Количество гостей (number), Город (select: Алматы, Астана, Шымкент).

- **Конструктор:** Edit/Preview, Undo/Redo, Reset.
- **Демонстрация State Reducer.** Переключатель «Ограничить 6 полями» включает `customReducer`, который отклоняет `ADD_FIELD` сверх лимита и показывает сообщение. На защите видно, что поведение изменилось снаружи, без правки FormProvider.
- **Секция «Компоненты ввода»:**
  - Input controlled с выводом значения рядом и Input uncontrolled с `defaultValue="Адильжан"`;
  - SearchInput и кнопка «Focus search»;
  - CustomInput и кнопки Focus, Clear, Get value. Get value выводит значение на страницу.

### Тесты №13

- **reducer:** каждое действие, переопределение через `customReducer`, Undo/Redo по сценарию из задания (add → change → delete → undo → undo → redo).
- **FormBuilder + FormPreview:** добавить поле, сменить тип, отметить обязательным, удалить. Preview показывает ошибки валидации, после правильного ввода Submit показывает объект значений.
- **Input:** controlled отражает `value` и вызывает `onChange` со строкой, uncontrolled показывает `defaultValue` и меняется без родителя.
- **SearchInput:** «Focus search» ставит фокус на input.
- **CustomInput:** Focus, Clear и Get value работают как описано выше.

2. **«Сеансы» — расписание для информации.**

3. **Вход по учётным записям в localStorage.**
   - `services/api.js` имитирует сервер: `register` сохраняет аккаунт (имя, email, пароль, город, пол) в localStorage и отклоняет уже занятый email («Такой email уже зарегистрирован»).
   - `login` проверяет пару email+пароль. При ошибке возвращает «Неверный email или пароль», форма показывает это над кнопкой. При успехе в шапку подставляется имя из регистрации.
   - Есть демо-аккаунт, чтобы войти без регистрации: «Жумагали Адильжан», `adilzhan@cinevibe.kz`, пароль подсказан на странице входа.
   - Пароль хранится как SHA-256 через `crypto.subtle` (решение автора дизайна: даже в демо не держать пароль открытым текстом). Если в jsdom это не заработает, исполнитель хранит открытым текстом с комментарием «только демо».

### Что такое «товар»

Магазин кинотеатра продаёт **билеты на фильмы** и **товары кинобара** (попкорн, напитки, снеки, комбо, мерч). Обе группы — товары одного каталога.

- Общие поля: `id`, `type` (`movie` | `bar`), `title`, `price`, `rating`, `category`, `imageUrl`, `description`.
- У фильмов есть ещё `year`, `duration`, `reviewsCount`, `status`, `isAvailable`. У товаров бара доп. полей нет.
- **id уникальны по всему каталогу:** фильмы сохраняют свои 1–12, товары бара получают 101+. Тогда `/products/:id` однозначен, корзина и избранное хранят просто id, и коллизий между фильмом и попкорном нет.
- У товаров бара сейчас нет описания и картинки. Их надо дописать коротко, а картинку генерировать тем же `createPoster` по категории.

### Данные и API

- Каталог лежит в `public/api/`. **Одно место — источник данных.** Данные о товарах не импортируются в код напрямую из `src/data`.
- Список: `GET /api/products.json`. Товар: `GET /api/products/<id>.json`. Деталь каждого товара — отдельный файл, чтобы страница товара делала свой запрос по id из `useParams`.
- **`services/api.js`** — единственное место с адресами: `API_BASE`, `productsUrl()`, `productUrl(id)`, а также `homeUrl()`, если главной нужен свой запрос.
- **`hooks/useFetch.js`** из ДЗ №10 используется без изменений API.

### Каталог `/products`

- `useFetch(productsUrl())` → все четыре состояния:
  - loading: `<Loader />` через `withLoading`;
  - error: `<ErrorMessage>` с «Повторить» (`refetch`);
  - empty: `<EmptyState message="Товары не найдены">` с «Изменить запрос»;
  - success: ProductList.
- **Раздел:** «Все / Билеты / Кинобар» (`type`).
- **Категория:** список зависит от раздела — жанры или категории бара.
- **Сортировка:** по рейтингу, цене ↑/↓, названию.
- **Поиск** по названию через `useDebounce` (300 мс). Все параметры живут в URL (`useSearchParams`), чтобы ссылкой на отфильтрованный каталог можно было поделиться.
- Фильтрация + сортировка — `useMemo`. Обоснование: пересчёт только при смене данных или параметров, а не при каждом вводе до debounce и не при смене темы.

### Детальная страница `/products/:id`

- `useParams` → `useFetch(productUrl(id))`. Несуществующий id даёт понятную ошибку 404 и ссылку в каталог.
- Кнопка «Назад» вызывает `useNavigate(-1)`. Если истории нет (страница открыта по прямой ссылке), ведёт на `/products`.
- **Фильм:** Tabs (Описание / Сеансы / Отзывы с ReviewForm), выбор количества билетов, «В корзину», «В избранное».
- **Товар бара:** описание, количество, «В корзину», «В избранное».

### Корзина `/cart` и CartContext

- CartContext на **`useReducer`** (actions `ADD`, `REMOVE`, `SET_QUANTITY`, `CLEAR`, `PLACE_ORDER`) с сохранением в localStorage, как сейчас. Это закрывает пункт «useReducer — сложное состояние».
- В корзине хранится минимальный снимок товара: `id`, `type`, `title`, `price`, `imageUrl`, `quantity`. Корзина должна показываться без повторной загрузки каталога, а цена фиксируется на момент добавления.
- Лимит количества: билеты до 10 на фильм, как сейчас. Для товаров бара лимит тоже есть (например, 20) — на усмотрение исполнителя.
- **Страница корзины:** CartList → CartItem (количество, «Удалить» с Modal-подтверждением), CartSummary (общая стоимость), промокод, «Оформить заказ» (только для вошедших, иначе ссылка на вход с возвратом). После оформления заказ появляется в `/profile/orders`.
- **Промокод:** скидка считается в корзине, но в контекст не сохраняется. Например, `CINEVIBE10` даёт −10%.

### Избранное

- FavoritesContext хранит **только id** (как сейчас).
- Страница `/favorites` загружает каталог через `useFetch(productsUrl())` и показывает товары, чьи id в избранном. Список избранных товаров целиком нигде не хранится — это и есть «не дублировать информацию».
- Пустое избранное показывается через `EmptyState`.

### Формы и авторизация

**`/login`:**
- email, пароль, select «Город» (Алматы, Астана, Шымкент, Караганда…), чекбокс «Запомнить меня»;
- «Войти» и «Сбросить»;
- валидация, ошибки под полями.

«Запомнить меня» решает, где хранится сессия: в localStorage (переживает закрытие браузера) или в sessionStorage.

**`/register`:** имя, email, пароль, подтверждение, select «Город», radio «Пол», чекбокс «Согласен с правилами», «Зарегистрироваться» и «Сбросить».

- Обе формы — controlled, на FormProvider + DynamicField из №13.
- Тексты ошибок переиспользуют `utils/validation.js`.

**AuthContext** хранит пользователя и сессию.
- Методы: `login`, `register`, `logout`, `isAuthenticated`. Регистрация сразу выполняет вход.
- Имя из учётной записи показывается в шапке и профиле. У демо-аккаунта имя «Жумагали Адильжан».

**ProtectedRoute** без входа ведёт на `/login` и сохраняет, куда пользователь шёл. После входа пользователь возвращается туда.

### Оптимизация — только обоснованная

Каждое использование сопровождается комментарием «почему».

- **`React.memo`:** у `ProductCard` в `ProductList` (десятки карточек, при вводе в поиск и смене количества в шапке родитель перерисовывается) и, если нужно, у `CartItem`.
- **`useCallback`:** у функций, которые передаются в эти memo-компоненты (`onToggleFavorite`, `onAddToCart`, `onRemove`, `onQuantityChange`). Функции контекстов стабильны через `useCallback` + `useMemo(value)` — без этого перерисовываются все потребители.
- **`useMemo`:** фильтрация и сортировка каталога, итоги корзины, производные списки (избранные товары из каталога).
- **Убрать:** всё, что было ради демонстрации ДЗ №9 (переключатель, «1000 товаров», `ProductStats`, если он больше не нужен).

### Повторяющаяся логика

- **Хуки** — то, что встречается на 2+ страницах: заголовок документа, загрузка каталога, логика избранного.
- **Утилиты:** форматирование цен и дат, валидация, localStorage.
- **Компоненты:** состояния loading/error/empty одинаковы на всех страницах с данными.
- Импорты единообразны: сначала внешние, затем внутренние, со стилями в конце, всегда с расширением `.jsx`/`.js`, как сейчас.

### Тесты hw14 (`src/tests/`, Vitest + RTL)

Общий помощник `renderApp(initialEntries)` рендерит `App` в `MemoryRouter` с подменёнными `matchMedia`/`scrollTo`. `fetch` подменяется ответами из тестовых данных (по образцу `test/mockUsers.js`).

**Сценарии из задания:**
1. Открытие каталога: loading, затем карточки.
2. Поиск товара: debounce и фильтрация. Пустой результат даёт EmptyState.
3. Открытие товара: клик ведёт на `/products/:id` с правильным заголовком, «Назад» работает.
4. Добавление в корзину: счётчик в шапке, товар на `/cart`, сумма.
5. Удаление из корзины: через подтверждение в Modal. Изменение количества меняет сумму.
6. Регистрация: ошибки валидации, после правильного ввода — вход и имя в шапке. «Сбросить» очищает форму.
7. Вход: пустые поля и неверный формат дают ошибки под полями; неверный пароль — «Неверный email или пароль»; правильная пара — вход, имя из регистрации в шапке, переход в профиль.
8. Доступ к защищённому профилю: без входа — `/login`, после входа — возврат в `/profile`.

**Маршрутизация:**
- каждая страница из списка открывается;
- неизвестный URL и `/404` показывают NotFound;
- `/profile/orders` и `/profile/settings` без входа ведут на `/login`, с входом рендерятся внутри ProfileLayout (Outlet);
- старые адреса перенаправляют.

**Компоненты:** тесты №12/13, которые остаются актуальными, переезжают в `src/tests/` (Tabs, Toggle, Accordion, DataLoader, withLoading, Input, SearchInput, CustomInput, form reducer). Плюс тесты общих компонентов (Button, Modal, EmptyState, Loader, ErrorMessage), useFetch, useDebounce, CartContext reducer.

## Мелкие решения автора дизайна (после проверки)

- **Undo/Redo (№13):** история оборачивает стандартный reducer снаружи. В неё попадают только `ADD_FIELD`/`REMOVE_FIELD`/`UPDATE_FIELD`. `RESET_FORM` возвращает стартовые поля, очищает значения, ошибки и историю.
- **Регистрация:** пароль от 6 символов, подтверждение должно совпадать, без галочки «Согласен с правилами» отправить нельзя. Все проверки идут через ту же валидацию FormProvider.
- **Отзывы о фильме:** хранятся в localStorage по id товара, как сейчас делает ReviewForm. Стартовые отзывы приходят в JSON товара.
- **Лимит количества:** для товаров бара — 20 штук на позицию.
- **Несуществующий JSON:** dev-сервер Vite может отдать `index.html` вместо 404. `services/api.js`/страница товара должны отличать такой ответ (не JSON или не тот content-type) и показывать «Товар не найден». Это проверяется руками в dev и `vite preview`.
